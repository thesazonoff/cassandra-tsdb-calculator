# ADR 0001. Стек и структура исходников

**Статус:** принято, версия 2.2.0
**Дата:** 2026-11-10

## Контекст

До версии 2.1 в репозитории лежал только собранный `index.html` (422 КБ). Внутри него две страницы в base64, каждая со своей копией движка отказоустойчивости, склеенные через `iframe`. Исходники, тесты и стенд проверки на Cassandra 5.0.9 хранились вне репозитория. Pull request нельзя было прочитать, файл нельзя было пересобрать, CI ничего не проверял.

Требования владельца:

- главное — производительность и легковесность, стек не важен;
- в релизе один HTML, который открывается без сервера и интернета;
- исходники и тесты в репозитории;
- сервер, авторизация и интеграция с MES не нужны;
- поддерживает один человек вместе с Claude.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. ES-модули на JavaScript, проверка типов `tsc --checkJs`, сборка esbuild в один HTML** | Нет зависимостей во время работы. Исходник и исполняемый код совпадают: unit-тесты запускают `src/` в Node без компиляции. Одна зависимость сборки (esbuild, один бинарник). Перенос с 2.1 без переписывания логики, проверяется регрессией | Типы проверяются мягче, чем в строгом TypeScript. Разметка строится строками HTML, без компонентной модели фреймворка |
| B. TypeScript + Vite + Preact или Svelte, single-file плагин | Строгие типы, компоненты, реактивность | +30–60 КБ рантайма, 200+ пакетов разработки, переписывание интерфейса двух страниц (3–5 итераций), риск расхождения с проверенными расчётами |
| C. Сервер (API + SPA) | Общие расчёты, история, доступ по ролям | Нужна инфраструктура и эксплуатация; противоречит требованию работать без сервера; функции сервера не нужны |
| D. Оставить как есть | Ноль работы | Технический долг из раздела «Контекст» остаётся |

## Решение

Вариант A.

- `src/core` — расчёт без DOM, общий для двух страниц. Один `fault.js` вместо двух копий.
- `src/pages/<страница>` — разметка, стили, контроллер состояния и представления. Представления — чистые функции, возвращают HTML.
- `src/app` — точка входа и адрес `#<страница>&s=<состояние>`. Без `iframe`: обе страницы в одном документе, стили изолированы вложением в `.pg-<страница>`, `id` второй страницы с префиксом `ft-`.
- `scripts/build.mjs` — сборка esbuild: JS в IIFE, CSS с раскрытием вложенности под браузеры 2022+, вставка в `src/index.html`, бюджет 400 КБ, запрет внешних ресурсов и повторяющихся `id`.
- Тесты: `node:test` для `core` и представлений, регрессия к 2.1.0 на 34 сценариях, Playwright для собранного файла, снимки текстов вкладок.
- `verification/` — эталонная модель формата SSTable и стенд на Cassandra 5.0.9; быстрая часть в CI, полная по кнопке.

## Последствия

- Размер файла 305 КБ вместо 422 КБ (−28 %): нет base64 и второй копии движка, код минимизирован.
- Вторая страница создаётся при первом открытии, стартовая страница не тратит на неё время.
- Любое изменение цифр или текстов видно в CI: регрессия к 2.1.0 и снимки текстов.
- Переход на TypeScript (вариант B без фреймворка) остаётся возможным по одному модулю: начинать с `src/core`, JSDoc-типы уже проверяются.
- Компоненты второй страницы (кнопки, карточки, таблицы) пока свои, на общих токенах. Перевод на общие классы первой страницы — отдельная задача без влияния на расчёт.
